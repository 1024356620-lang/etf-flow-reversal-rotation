# ETF 资金流反转效应指数轮动策略复现

复现中泰证券金融工程专题报告《指数应用研究系列二：基于ETF资金流反转效应与持有人结构异质性的指数轮动策略》（2026-03-15）。

本项目从 CSMAR 原始数据出发，完成数据清洗、因子构建、样本池筛选、选股、月度回测与绩效评估，并重点记录了复现过程中遇到的数据工程问题、回测引擎修复过程，以及账本内部一致性的逐日核验方法。

---

## 策略逻辑

| 模块 | 规则 |
|---|---|
| 样本池 | 指数上日 ETF 跟踪规模 > 5 亿元，且机构占比 < 70% |
| 因子 | 10 日累计 ETF 资金流强度（份额变动 × 收盘价 / 上日跟踪规模），半年度分位标准化（实现口径见"已知局限"） |
| 调仓 | 月度，月初首个交易日收盘 |
| 选股 | 剔除资金净流入（`flow_cum > 0`），选资金流出最强的最多 5 个指数 |
| 目标仓位 | 每个指数目标仓位为账户净资产的 20%；宽基缺额保留现金，不以其他指数补足 |
| 宽基约束 | 预留 3 个宽基仓位；宽基不足时缺额保留现金；非宽基最多补 2 个 |
| 成本 | 证券权重差近似交易成本，单边 0.1%；现金划转不计费 |

**核心假设**：低机构占比（个人投资者主导）指数的资金流呈现反转效应——个人投资者"追涨杀跌"，资金流出最强的指数未来收益最高。高机构占比指数该效应不显著，因此样本池剔除机构占比 ≥ 70% 的指数。

## 回测可信度核验

回测引擎已通过独立脚本 `tests/verify_account.py` 逐日复算。**核验范围是账本内部一致性**，不包含原始行情准确性、信号可用时点、宽基分类准确性、因子有效性。

| 核验项 | 结果 |
|---|---|
| `[0]` 每日资产权重 + 现金权重 = 1 | 1719 天全部满足，最大偏差 7.8e-16 |
| `[A]` 上日权重 > 0 的资产当日收益覆盖 | 无缺失、无非有限值；`holdings_returns` 覆盖全部持仓日期 |
| `[B]` `market_ret` = 前一日权重 × 当日收益 | 1715 天，最大误差 1.1e-16 |
| `[C]` 权重漂移 `w_t = w_{t-1}(1+r_t)/(1+R_t)`，现金同理 | 非调仓日、调仓日 `old_weights/old_cash`、调仓后 `new_weights/new_cash` 全部满足 |
| `[D]` 换手（含现金）与成本（只含证券）复算 | 一致；`account` 与 `rebalance_detail` 的 `turnover/cost` 对齐 |
| `[D2]` `net_ret = market_ret - cost`，`cost = (1+market_ret)×traded_fraction×cost_rate` | 恒等式成立，成本基数换算一致 |
| `[E]` 选仓约束：`n_selected≤5`、`non_broad_n≤2`、宽基不足时 `n_selected≤broad_n+2` | 85 个月全部满足 |

### 成本口径

采用证券权重差近似交易成本。`traded_fraction` 是证券买卖金额占当日收盘扣费前净资产的比例；`cost = (1+market_ret) × traded_fraction × cost_rate` 换算为占上日净资产的比例，与 `market_ret`、`net_ret` 同基数。`turnover` 含现金，仅用于统计资产配置变化；现金划转不计费。

### 宽基约束

预留 3 个宽基仓位，缺额保留现金，不以其他指数补足。回测期内 13 次触发：9 次现金 20%（宽基 2 个），4 次现金 40%（宽基 1 个）。这些月份**执行了预定降仓规则，不代表约束执行失败**。`diagnostics.csv` 记录 `broad_n`、`non_broad_n`、`cash_slots`、`cash_weight_implied`、`broad_shortfall_reason`。

### 账本文件

`results/` 下：

| 文件 | 内容 |
|---|---|
| `account.csv` | 每日 `market_ret`、`cost`、`net_ret`、`turnover`、`traded_fraction`、`fee_fraction`、`n_holdings`、`cash_weight` |
| `daily_weights.csv` | 每日每指数权重（占总资产） |
| `cash_weights.csv` | 每日现金权重 |
| `rebalance_detail.csv` | 调仓日换仓前/后权重、现金权重、换手、证券交易比例、费用、成本 |
| `holdings.csv` | 每月调仓持仓列表 |
| `diagnostics.csv` | 每月选仓诊断（宽基数、非宽基数、现金仓位、降仓原因） |
| `holdings_returns.csv` | 上日实际持仓 × 当日收益（缺失保留 NaN） |
| `index_returns.csv` | 完整收益面板 |

## 与研报的可能差异

年化 14.20% vs 研报 16.75%，差距约 2.5 个百分点。以下为**可能影响结果的差异**，尚未做受控实验量化各项贡献，不按影响大小排序：

1. **样本池覆盖**：本复现日均 37 个指数；研报称 2020 年以来有效可投指数始终维持在 40 个以上（研报图表 21）。两者统计期间不同，不能直接比较。样本池较小会减少宽基候选，增加降仓触发频率。
2. **宽基约束实现**：研报未明确宽基不足时的处理。本复现采用"预留 3 个宽基仓位、缺额留现金"的硬约束，13 次触发。软约束版（宽基不足时补足 5 个）在**当前修复后的引擎、成本口径和分类**下年化为 10.67%（早期未修复引擎时为 10.31%，该数字已废弃，不应与 10.67% 混用）。两版差异只有在**相同数据、费用、信号、分类和引擎，仅改变约束**时才能归因于约束；当前软约束版是在引擎修复过程中得到的，尚未在最终冻结版上重新对齐。
3. **基准口径**：本复现用中证全指（000985）价格指数；研报用万得全A 全收益指数（研报图表 25）。价格指数不含股息再投资，且两个指数成分不同，主动收益不可直接比较。
4. **回测起点**：本复现样本池从 2019-01 开始（2017–2018 年 CSMAR ETF 数据覆盖不足），研报从 2017-01 开始。回测起点不同，比较结果受市场区间影响。

**已撤回的旧结论**：

- 旧版"差距来自数据源限制，非代码问题"不成立——回测引擎曾存在持仓估值被样本池污染、成本覆盖收益、每日重新等权三个 bug。修复后重跑，软约束版年化从 11.51% 变为 10.31%，再经硬约束和成本口径修正后为 14.20%。这些数字对应不同修复阶段，不应混用。
- 旧版"价格指数不含股息，超额被低估 1.5–2%/年"方向说反了——对同一基准，价格指数收益低于全收益指数，策略相对价格指数的超额应该更高，不是被低估。
- 旧版"6/7 个年度方向一致，验证了策略核心逻辑"是弱证据。年度涨跌同向不能区分"策略逻辑有效"和"beta 暴露碰巧同向"。

## 已知局限（后续研究核验范围）

本次账本 PASS **不证明**以下事项成立：

1. **原始行情准确性**：CSMAR 的 ETF 行情、份额、指数行情是否与交易所/Wind 一致，是否存在复权、停牌、退市处理问题。账本内部自洽不能排除源数据错误。
2. **信号可用时点**：`flow_cum` 使用 T 日份额变动，调仓在 T 日收盘。若份额数据为盘后或 T+1 披露，存在前视偏差。需要确认 CSMAR 字段披露时点，或做信号滞后一天的对照测试。
3. **半年度分位标准化的实现口径**：当前代码按**自然半年**（`to_period('2Q')`）对 `flow_cum` 做截面 `rank(pct=True)`。这意味着同一半年内较晚日期的排名用到了该半年内较早日期的数据，但**不会用到未来数据**；不过它不是"过去半年滚动窗口"。研报原文只写"半年度分位数标准化"，未明确是滚动还是自然半年。若研报意图是滚动窗口，当前实现与之不同，需要重做因子并重跑。仅凭当前 README 无法确认研报口径，列为待核验。
4. **宽基分类准确性**：`_is_broad` 基于 `BROAD_BASE_CODES` 集合与 `SECTOR_KEYWORDS['宽基']` 关键词并集，尚未逐一核对每个指数（尤其 `399975`、`399989` 等边界标的）是否应归为宽基。分类偏差会直接影响宽基约束触发频率和降仓结果。
5. **因子有效性**：尚未用 Rank IC、分组收益、同池等权对照检验。2022/2023 年亏损 -20.09% / -18.59%，需要区分是宽基约束失效、样本池 beta 拖累，还是资金流反转信号在熊市失效。

## 后续研究计划

按优先级：

1. **信号可用时点核查**：确认 CSMAR 份额字段披露日期；若为 T+1，做信号滞后一天的对照，比较年化和 2022/2023 年亏损。
2. **半年度分位标准化口径确认**：核对研报原文或补充材料，确认是自然半年还是过去半年滚动窗口。若为滚动窗口，重做因子并重跑。
3. **宽基分类核对**：列出 `BROAD_BASE_CODES ∪ SECTOR_KEYWORDS['宽基']` 在 85 个月里出现过的代码，逐一核对分类；重点检查 `399975`、`399989`、`399905`、`399300`、`000905`。
4. **样本池覆盖**：检查 `ETF.csv` 的拟合指数映射是否漏了大量宽基/行业 ETF，`csmar_index_daily_clean.csv` 是否缺失指数行情。目标是以**历史真实覆盖、筛选规则和数据质量**为准，而不是以"接近研报的 200 个"为目标。
5. **因子有效性检验**：这一步需要**新增数据导出**，`holdings_returns.csv` 和 `diagnostics.csv` 不足以完成：
   - `holdings_returns.csv` 只含已选资产，有选择偏差；
   - `diagnostics.csv` 没有全体候选的因子值；
   - 同池等权需要当时整个合格样本池及其后续收益。

   应新增一张**信号日候选表**，每个调仓日一行一指数，字段包括：`trade_date`、`index_code`、`flow_cum`、`flow_cum_std`、`flow_pct`、`eligible`（是否在样本池）、`selected`（是否被选中）、`forward_ret_1m`（下月收益）、`signal_available_date`（信号实际可得日期）。基于这张表再做：
   - Rank IC：每个调仓日 `flow_cum` 与 `forward_ret_1m` 的 Spearman 相关，看时序均值和 t 统计量；
   - 分组收益：按 `flow_cum` 分 5 组，看 TOP vs BOTTOM 的下月收益差；
   - 同池等权：用 `eligible=True` 的全部候选等权持有，与策略持仓对比，差值才是选股能力。

   检验目的是**预测方向、稳定性及统计不确定性**；单个年度的 IC 变化不足以证明信号失效或排除其他原因。
6. **软约束版在冻结引擎上重新对齐**：当前软约束版 10.67% 是在引擎修复过程中得到的，未在最终冻结版上重跑。若要做软/硬约束对照，需在相同数据、费用、信号、分类和引擎下重跑软约束版，才能归因于约束本身。

## 运行

### 环境

```bash
pip install -r requirements.txt
```

### 数据准备

将以下 CSMAR 数据文件放入 `raw_data/`（数据有版权，不随仓库分发）：

| 文件 | 内容 | 来源 |
|---|---|---|
| `ETF.csv` | ETF 基本信息（代码、拟合指数、简称、规模） | CSMAR 基金数据库 |
| `FUND_MKT_Quotation*.csv` | ETF 日行情（收盘价、流通份额） | CSMAR 基金市场行情 |
| `csmar_index_daily_clean.csv` | 指数日行情（代码、日期、收盘价） | CSMAR 指数日行情 |
| `Fund_HolderStructure.csv` | ETF 持有人结构（机构占比） | CSMAR 基金持有人结构 |

可选：`wind_all_a.csv`（万得全A 日行情，列名 `trade_date, close`），若存在则优先作为基准。

### 执行

```bash
python src/strategy.py --flow-filter-mode absolute --min-etf-size 5e8
python tests/verify_account.py   # 应输出 PASS
```

输出：全样本绩效、分年绩效、`results/` 下八张表。

### 测试

```bash
pytest tests/ -v
```

`tests/test_backtest.py` 用合成数据锁死三个回测引擎 bug（调仓日收益被成本覆盖、月内每日重新等权、持仓估值被样本池污染）；`tests/verify_account.py` 用真实账本逐日核验。
